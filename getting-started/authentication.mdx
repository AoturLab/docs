HiLinkup 使用同一类账户 API Key，但请求头取决于你调用的协议。不能把所有 `/v1` 请求都当作 Bearer Token 接口。

| 协议 | 典型路径 | 必需鉴权头 |
| --- | --- | --- |
| OpenAI Responses、Chat Completions、Models、Embeddings、Images | `/v1/...` | `Authorization: Bearer YOUR_HILINKUP_API_KEY` |
| Claude Messages | `/v1/messages` | `x-api-key: YOUR_HILINKUP_API_KEY` 与 `anthropic-version: 2023-06-01` |
| Gemini generateContent | `/v1beta/models/{model}:generateContent` | `x-goog-api-key: YOUR_HILINKUP_API_KEY` |

<Warning>
  路径包含 `/v1` 不等于一定使用 Bearer Token。Claude Messages 同样位于 `/v1/messages`，但使用 `x-api-key` 和 `anthropic-version`。
</Warning>

## 创建和使用密钥

<Steps>
  <Step title="创建密钥">
    登录 [HiLinkup 控制台](https://hilinkup.com/console/token)，为应用创建独立密钥。
  </Step>
  <Step title="保存到服务端">
    将密钥保存到环境变量或密钥管理服务，不要发送到浏览器和移动端。
  </Step>
  <Step title="按协议添加请求头">
    OpenAI 兼容接口：

    ```bash
    curl https://api.hilinkup.com/v1/models \
      -H "Authorization: Bearer $HILINKUP_API_KEY"
    ```

    Claude Messages：

    ```http
    x-api-key: YOUR_HILINKUP_API_KEY
    anthropic-version: 2023-06-01
    Content-Type: application/json
    ```

    Gemini generateContent：

    ```http
    x-goog-api-key: YOUR_HILINKUP_API_KEY
    Content-Type: application/json
    ```
  </Step>
</Steps>

## 密钥管理建议

- 为开发、测试和生产环境创建不同密钥。
- 为不同应用或团队创建不同密钥，便于审计和撤销。
- 不要在日志中输出完整密钥。
- 怀疑泄露时立即撤销旧密钥并创建新密钥。
- 在 CI/CD 中使用平台的 Secret 功能，不要提交 `.env`。

<Warning>
  API Key 代表你的账户权限和可用额度。前端代码、公开仓库、截图和聊天记录都不是安全的保存位置。
</Warning>

## 认证错误

| 状态码 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `401` | 缺少、无效或已撤销的密钥 | 先确认协议，再检查对应鉴权头 |
| `403` | 请求被策略或上游服务拒绝 | 检查请求参数、模型权限和调用环境 |

<Tip>
  如果同一密钥调用 `/v1/models` 成功，但模型请求返回 `401`，优先检查是否把 Bearer、`x-api-key` 或 `x-goog-api-key` 用错，而不是重新创建密钥。
</Tip>

完整处理流程参见[错误排查](/troubleshooting/errors)。
