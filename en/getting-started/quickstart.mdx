This guide takes you from a new account to a verified model response.

<Info>API base URL: `https://api.hilinkup.com/v1`</Info>

## 1. Create an API key

<Steps>
  <Step title="Sign in">
    Open [HiLinkup](https://hilinkup.com/) and sign in.
  </Step>
  <Step title="Open API key management">
    Go to the [API key page](https://hilinkup.com/console/token).
  </Step>
  <Step title="Create a dedicated key">
    Name it after the application and environment, such as `local-development`. Copy it immediately and store it in a password manager or secret manager.
  </Step>
</Steps>

<Warning>Never commit an API key, send it in chat, or expose it to browser code.</Warning>

## 2. Save the key

<Tabs>
  <Tab title="macOS / Linux">

## 3. List available models

```bash
curl https://api.hilinkup.com/v1/models \
  -H "Authorization: Bearer $HILINKUP_API_KEY"
```

Example response:

```json
{
  "object": "list",
  "data": [
    {
      "created": 1785943362,
      "owned_by": "z-ai",
      "id": "z-ai/glm-5.2",
      "object": "model"
    },
    {
      "created": 1786358014,
      "owned_by": "aliyun",
      "id": "aliyun/kimi-k3",
      "object": "model"
    }
  ]
}
```

The response identifies each provider in `owned_by` and returns a provider-qualified `id`, such as `aliyun/kimi-k3`. Copy the full `data[].id` value to select that provider explicitly. If you send only `kimi-k3`, HiLinkup uses the platform's current default provider setting. The examples use `aliyun/kimi-k3`; replace it if that ID is not returned for your key.

<Check>HTTP `200` and a non-empty `data` array confirm that authentication and model access work.</Check>

## 4. Make a Responses request

Responses is the default for new code. Use Chat Completions only when an existing client requires it.

<CodeGroup>
```bash cURL
curl https://api.hilinkup.com/v1/responses \
  -H "Authorization: Bearer $HILINKUP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "aliyun/kimi-k3",
    "input": "Reply with: HiLinkup connected"
  }'
```

```python Python
# Install: python -m pip install openai
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["HILINKUP_API_KEY"],
    base_url="https://api.hilinkup.com/v1",
    timeout=60.0,
)

response = client.responses.create(
    model="aliyun/kimi-k3",
    input="Reply with: HiLinkup connected",
)

print(response.output_text)
print(response.usage)
```

```javascript Node.js
// Install: npm install openai
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.HILINKUP_API_KEY,
  baseURL: "https://api.hilinkup.com/v1",
  timeout: 60_000,
});

const response = await client.responses.create({
  model: "aliyun/kimi-k3",
  input: "Reply with: HiLinkup connected",
});

console.log(response.output_text);
console.log(response.usage);
```
</CodeGroup>

## 5. Verify the response

A successful response has:

- HTTP status `200`
- `status` set to `completed`
- Typed items in `output`
- Text in the SDK's `response.output_text` helper
- Token counts in `usage`

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Unauthorized">
    Check the Bearer token, environment variable, copied key, and whether the key was revoked.
  </Accordion>
  <Accordion title="403 Forbidden">
    Check account status and model permissions. List models again and select an ID returned for this key.
  </Accordion>
  <Accordion title="404 Not Found">
    The complete endpoint is `https://api.hilinkup.com/v1/responses`. The SDK base URL is `https://api.hilinkup.com/v1`.
  </Accordion>
  <Accordion title="429 Too Many Requests">
    Reduce concurrency, check balance and limits, then retry with bounded exponential backoff.
  </Accordion>
  <Accordion title="Model not found">
    Copy the exact `data[].id` from `/v1/models`; do not use a display name from a screenshot or another account.
  </Accordion>
</AccordionGroup>

<Note>For a client that only supports the traditional OpenAI chat protocol, use [Chat Completions](/en/api-reference/chat-completions). The request body, output fields, streaming events, and tool format differ from Responses.</Note>
