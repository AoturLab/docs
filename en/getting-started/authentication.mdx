HiLinkup uses account API keys, but the header depends on the wire protocol. Do not send every `/v1` request with a Bearer token.

| Protocol | Typical path | Required authentication |
| --- | --- | --- |
| OpenAI Responses, Chat Completions, Models, Embeddings, Images | `/v1/...` | `Authorization: Bearer YOUR_HILINKUP_API_KEY` |
| Claude Messages | `/v1/messages` | `x-api-key: YOUR_HILINKUP_API_KEY` and `anthropic-version: 2023-06-01` |
| Gemini generateContent | `/v1beta/models/{model}:generateContent` | `x-goog-api-key: YOUR_HILINKUP_API_KEY` |

<Warning>A `/v1` path does not always mean Bearer authentication. Claude Messages uses `/v1/messages` with `x-api-key` and `anthropic-version`.</Warning>

Create separate keys for different applications and environments. Store keys in environment variables or a secret manager, never in source code.

<Warning>If a key is exposed, revoke it in the console and create a replacement immediately.</Warning>

If `/v1/models` works but an inference request returns `401`, verify the protocol-specific header before rotating the key.

See [error troubleshooting](/en/troubleshooting/errors) for `401` and `403` responses.
